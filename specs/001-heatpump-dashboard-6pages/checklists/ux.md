**Purpose**: 作者自審——在進入開發前，驗證 UX 與視覺設計需求的完整性、清晰度及一致性；並深入審查風險分數計算規格

**Focus**: UX／視覺需求品質（Q1-C）＋ 風險分數計算公式深入審查（Q3）

## 視覺設計規格清晰度

- [ ] CHK001 「深綠黑底色」是否以具體色彩值（HEX、HSL 或 RGB）定義，而非僅以感受描述？ [Clarity, Spec §FR-030]
- [ ] CHK002 「黃綠色系主要強調色」是否量化為完整色票（主色、互動態、停用態），避免實作者各自詮釋？ [Clarity, Spec §FR-030]
- [ ] CHK003 狀態語意色彩（綠／紅／灰／橘）是否涵蓋所有可能狀態值，且相鄰狀態（如「異常」vs「待維修」）的色彩差異是否足夠清晰可辨？ [Completeness, Spec §FR-031]
- [ ] CHK004 圖表在深色背景上「清晰可讀」的要求是否以 WCAG 2.1 AA 對比度（文字 ≥ 4.5:1、非文字 ≥ 3:1）量化，並定義主要文字、次要文字與停用文字的色彩層級？ [Ambiguity, Spec §FR-032]
- [ ] CHK005 所有互動元素（按鈕、篩選器、頁籤、可點擊行列）的懸停（hover）與鍵盤聚焦（focus）視覺狀態需求是否定義？ [Gap]
- [ ] CHK006 是否定義介面中的動態回饋需求（如設備狀態即時更新時的過渡效果或視覺脈衝）？ [Gap, Spec §US-1 AC3]

- [ ] CHK011 告警嚴重性等級的分類標準（何謂「高嚴重性」，如嚴重度 ≥ 某閾值？異常代碼類別？）是否在規格中明確定義？ [Gap, Spec §FR-020]
- [ ] CHK012 高嚴重性告警「紅色背景突出顯示」的具體色彩值、適用範圍（整行或僅部分欄位）是否定義？ [Ambiguity, Spec §FR-020]

- [ ] CHK014 用電紀錄折線圖的 X 軸（日期格式）、Y 軸（單位：kWh？）、刻度密度及數值標籤格式是否定義？ [Clarity, Spec §FR-012]
- [ ] CHK015 折線圖「標示異常值」的視覺方式（圓點標記？顏色變化？圖示？）是否有具體描述，而非僅說明「標示」？ [Ambiguity, Spec §FR-012]
- [ ] CHK016 圖表工具提示（tooltip）的觸發方式（hover？點擊？）及顯示的資料欄位格式是否定義？ [Gap]
- [ ] CHK017 圖表資料非同步載入期間的 Loading 狀態視覺呈現（骨架屏？旋轉圖示？）是否有需求定義？ [Gap]
- [ ] CHK018 當圖表無任何歷史資料（設備剛安裝當天）時的空狀態（empty state）顯示規格是否定義？ [Gap, Edge Case]
- [ ] CHK019 月報健康分數「分布圖」使用的圖表類型（長條圖？直方圖？散點圖？）是否明確指定，而非留給開發者自行決定？ [Ambiguity, Spec §FR-022]
- [ ] CHK020 老闆決策頁「產能曲線」的圖表類型、X 軸（設備數量）、Y 軸（產能利用率）的含義與刻度是否具體描述？ [Ambiguity, Spec §FR-029]
- [ ] CHK021 風險排序頁中排名變動標示（↑ ↓）的視覺規格（顏色、位置、大小）是否定義？ [Gap, Spec §FR-009]

## 風險分數計算公式需求品質（深入審查）

- [ ] CHK026 風險分數（0–100）的計算公式或加權演算法是否在 spec.md、data-model.md 或 contracts/ 中任何一處定義？ [Gap, Spec §FR-006]
- [ ] CHK027 構成風險分數的輸入變數（連續異常次數？能耗偏差百分比？未維修天數？）是否有完整且明確的列舉？ [Gap, Spec §FR-007]
- [ ] CHK028 各風險因子的權重比例（Weight）是否有具體數值定義，且所有因子權重加總是否說明為 100% 或其他固定基準？ [Gap, Spec §FR-007]
- [ ] CHK029 風險分數達邊界值（0 分代表無風險、100 分代表最高風險）時的業務含義是否在需求中定義？ [Clarity, Spec §FR-007]
- [ ] CHK030 當多台設備風險分數相同（並列）時，Top 10 清單的排序決勝規則（tie-breaking，如依設備編號、告警時間）是否定義？ [Gap, Spec §FR-006]
- [ ] CHK031 「風險主因說明」的文字產生規則（由哪個因子超過哪個閾值，觸發哪段說明文字）是否定義，以確保文字一致性？ [Gap, Spec §FR-007]
- [ ] CHK032 「建議行動優先級（緊急／本週／本月）」的判斷條件（如風險分數閾值區間或特定告警類型）是否明確定義？ [Gap, Spec §FR-008]
- [ ] CHK033 風險排名的更新觸發條件是否定義（定時輪詢 30 秒？特定事件觸發？兩者皆有？），以確認前後端輪詢策略一致？ [Gap, Spec §FR-009]
- [ ] CHK034 排名變動標示（↑ ↓）的對比基準是哪次快照（上次輪詢？上一小時整點？每日重置？）是否定義？ [Ambiguity, Spec §FR-009]

## 備註

| 標記 | 含義 | 建議行動 |
|------|------|---------|
| `[Gap]` | 需求完全缺漏 | 補充至 spec.md 對應 FR 段落 |
| `[Ambiguity]` | 需求存在但描述模糊 | 量化或明確化用語 |
| `[Clarity]` | 需求存在但實作者可能有不同理解 | 加入範例或具體數值 |
| `[Conflict]` | 多條需求間存在潛在矛盾 | 確認優先順序並統一描述 |
| `[Recovery Flow]` | 例外恢復流程未涵蓋 | 補充邊界情況章節 |

**最高優先建議**：CHK026–CHK034（風險分數計算）為本次審查最高風險區域，建議在開發 Phase 5（US2 風險排序）啟動前完成補充，否則前後端對計算邏輯的假設將產生分歧。
